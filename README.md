# xhs-douyin-engagement-snapshot

面向 Codex 的小红书与抖音互动内容增量快照技能。

它默认扫描前 3 屏，从小红书点赞/收藏和抖音喜欢/收藏列表中增量发现内容，按稳定 ID 去重；随后理解小红书封面图与抖音开场 0—3 秒（必要时至 8 秒），把公开表现按平台内同指标标准化，再形成可进入人工筛选和 B 阶段点击测试的候选。

## 主要能力

- 小红书点赞、收藏与抖音喜欢、收藏视频的增量扫描
- 按平台、列表类型和内容 ID 去重
- 保存历史、差异、覆盖状态与可选深读证据
- 小红书理解封面文字、主体、构图、视觉风格和封面—标题关系
- 抖音理解开场关键帧、屏幕文字、可见字幕/口播和时序钩子
- 把“3.3万”等公开指标数值化，并按平台、媒体类型和列表计算同指标百分位
- 先形成至少两条独立内容支撑的证据组，再生成建议标题，避免先有结论再找链接
- 最终主报告优先输出由反差、冲突、失败现场、数字、反常识或信息缺口驱动的建议标题
- 保留门店社群业务倾向，但把行业落点与标题表面词汇分开，避免所有标题同质化
- 每次执行前检查 GitHub `main` 是否有更新；有更新先同步，再进行浏览器操作
- 可选生成飞书 Base 待定候选预览，写入前保留人工确认闸门

默认只读，不会自动点赞、收藏、关注、评论、私信或发布内容。飞书写入默认关闭。

## 使用与边界

完整参数、采集流程、持久化结构、源同步和安全边界请查看 [SKILL.md](SKILL.md)。

示例：

```text
运行 xhs-douyin-engagement-snapshot，平台 xhs,douyin，列表 liked,favorited,favorited_videos，前 3 屏增量扫描；理解小红书封面和抖音开场 3 秒，不做完整详情深读，不写飞书。
```

每次运行的主报告应先给少量建议标题，例如带有反差、失败现场、数字/时间/价格、反常识或信息缺口的可读文本；随后说明这些注意力母题如何落到门店社群，并附标题机制、原始证据、深读建议和覆盖边界。不得只输出“社群、私域、亲子、AI”等关键词，不得让所有标题重复“门店/社群/客户”，也不得把一次样本称为 TOP 或爆款。

## 辅助脚本

- `scripts/merge_snapshot.py`：合并本次快照、追加历史并生成保守差异。
- `scripts/analyze_titles.py`：提取标题机制特征，不自动判断爆款或选择 TOP。
- `scripts/normalize_metrics.py`：解析公开指标，按同平台同指标计算百分位，不直接跨平台比较绝对值。

三个脚本仅依赖 Python 标准库。
